# Bounded Bedrock Grounding Recovery Design

## Goal

Prevent chat requests from remaining indefinitely on “Investigating current project evidence...” when Bedrock repeatedly returns non-empty prose that the grounding validator rejects.

## Selected design

- Keep every successful user-visible chat answer generated by Amazon Bedrock.
- Keep normal grounding validation and bounded corrective Bedrock retries.
- Separate semantic/grounding retries from transport retries.
- Limit grounding repair to the configured `max_attempts` value (three in the local application).
- After grounding repair is exhausted, return the latest non-empty Bedrock response instead of validating forever or producing deterministic text.
- Continue persistent retry behavior only for Bedrock transport failures such as timeouts, throttling, and temporary service errors.
- Log when the bounded grounding escape is used, including the correlation ID and validation reason.
- Preserve the existing browser cancellation control and responsive interface.

## Verification

- A unit test proves persistent transport mode cannot make grounding retries infinite.
- The test asserts the returned response source is `bedrock` and the final text is the latest Bedrock output.
- Existing grounded-answer tests continue to pass.
- The local container is rebuilt and verified on port 8000.
