# Universal Grounded Evidence Answering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every WFD project question use relevant structured Jira MCP and workforce evidence, retain structured follow-up references, and let Bedrock produce a concrete grounded answer or a precise last-resort missing-data request.

**Architecture:** Normalize the Bedrock evidence plan without imposing a fixed intent whitelist, derive a typed `AnswerEvidenceSet` from the existing bounded project snapshot, and give that focused set to Bedrock. Validate claims and completeness against the focused set, then persist its task and employee references as conversation context.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, LangGraph, Amazon Bedrock, Atlassian Rovo MCP, pytest, JavaScript, Docker Compose.

## Global Constraints

- Every successful user-visible chat answer is generated by AWS Bedrock.
- Deterministic code selects, normalizes, derives, and validates evidence but does not write final chat prose.
- Risk scores and levels remain deterministic and unchanged.
- The assistant is not limited to a fixed supported-intent whitelist.
- Jira and workforce evidence is read-only in this workflow.
- Generic insufficiency is allowed only after relevant reads and only for a concrete missing field or ambiguity.
- Transient Bedrock failures retain the persistent `Bedrock is still working...` browser retry behavior.
- No Jira mutation, scoring redesign, UI redesign, deployment, or infrastructure change is included.

```python
class AnswerTaskEvidence(BaseModel):
    key: str
    summary: str
    status: str
    priority: str
    assignee: str | None
    due_date: date | None
    remaining_hours: float | None
    blocker: str | None
    dependencies: tuple[str, ...]
    blocked: bool
    blocks_downstream: tuple[str, ...]
    overdue: bool
    due_soon: bool
    missing_fields: tuple[str, ...]


class AnswerEmployeeEvidence(BaseModel):
    employee_id: str
    display_name: str
    role: str | None
    skills: tuple[str, ...]
    capacity_hours: float | None
    remaining_hours: float | None
    available_capacity_hours: float | None
    active_tasks: int
    risk_level: str
    top_risk: str
    task_keys: tuple[str, ...]


class AnswerEvidenceSet(BaseModel):
    question_focus: str
    tasks: tuple[AnswerTaskEvidence, ...] = ()
    employees: tuple[AnswerEmployeeEvidence, ...] = ()
    exhaustive: bool = False
    missing_data: tuple[MissingData, ...] = ()
```

Use frozen, `extra="forbid"` models like the existing evidence types.
